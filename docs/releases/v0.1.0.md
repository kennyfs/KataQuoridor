# KataQuoridor 0.1.0

*Proposed tag: `kq-v0.1.0`.* The repository still carries upstream KataGo's tags (`v1.0` … `v1.18.x`), so
KataQuoridor tags use a `kq-` prefix to stay unambiguous.

First release of KataQuoridor, a Quoridor (Duel) engine and training pipeline based on KataGo 1.18.2. The engine
plays through QTP (GTP with Quoridor moves), trains through KataGo's self-play loop, and comes with a
match referee and Elo ladder for evaluation. This release ships a first trained net that clearly beats simple
search bots with its policy alone.

in the ladder below.

## Changes

### QTP

- **Game over is final.** Once a pawn reaches its goal, `play`, `move`, `wall`, `genmove` and all
  `genmove`/`kata-search`/analysis variants fail with `? game is over`; `legal_moves` is empty and `winner`
  keeps the result. Before, moves were still accepted after a win, and `winner` went back to `none` if the
  winner stepped off its goal row. `undo`, `clear_board`, `loadsgf` and `set_position` still work.
- **Turn order is enforced.** Quoridor strictly alternates and has no pass. `play`/`move`/`wall` for the side
  not to move fail with `? illegal move: not <color>'s turn`; `genmove`, `kata-search` and `kata-analyze` for
  that colour fail with `? not <color>'s turn`. Before, the engine silently handed that colour the move, which
  amounted to a pass by the other side.
- `name` returns `KataQuoridor`; `version` returns
  `KataQuoridor 0.1.0 (based on KataGo 1.18.2, git <sha>)` (it used to be `1.18.2+<model name>`).
- Regression tests: `python/tests/test_qtp_rules.py`.

### Versioning

- KataQuoridor has its own version, `0.1.0` (`Version::getKataQuoridorVersion()`), shown by `katago version`,
  `--version`, QTP `version` and the startup log. The upstream base version (`getKataGoVersion()`) stays at
  `1.18.2`, so upstream code that reports or compares it (e.g. the analysis engine's `query_version`) is
  unchanged. The net format is unchanged: architecture version 17, Quoridor I/O version 1.

## Known limitations

- **First-player advantage, no komi.** Between strong players Black (the first player) wins about 59–65% of
  games, and there is no komi or other compensation yet (planned as "Quoridor I/O v2", Phase 6 of the
  [roadmap](../KataQuoridor_Review_and_Roadmap.md)). Evaluate with colour-swapped pairs.
- **Rare 300-ply draws.** Against weak opponents, games occasionally end in a corridor blockade where neither
  side makes progress until the 300-ply cutoff (38 of 5324 ladder games, 0.7%, mostly involving early
  snapshots or the SimpleQuoridor search bots).
- **No ownership output.** The net has no ownership head, so KataGo's ownership features (e.g. `ownership` in
  analysis) are not available.
- **The gatekeeper overstates per-generation gains.** Its match results make each new net look like a bigger
  step than the arena ladder shows; use the ladder, not gatekeeper win rates, to measure progress.
- Supported backends are CUDA and Eigen only; OpenCL, TensorRT and Metal refuse to load a net, and ROCm and the
  C++ ONNX backend are untested.
- Only the Duel mode (9 × 9, two players) is implemented.
- Some upstream subcommands are still Go-specific. `katago benchmark` aborts ("Illegal move in SGF") because it
  replays a built-in Go game, and `genconfig` is untested. The entry points used and tested so far are `gtp`,
  `selfplay`, `gatekeeper`, `runtests` and `version`.
