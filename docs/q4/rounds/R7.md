## 2. Part A: population self-play (as implemented)

- **Composition** (`q4population.{h,cpp}`, `sampleComposition`): with probability `1 − q4PopulationMixedProb` all four
  seats are learners; otherwise the number of learners is uniform in {1,2,3}, their seats uniform (partial Fisher–Yates), and each
  other seat draws a kind with `q4PopulationWeights` (snapshot excluded if none exists, i.e. redrawn). `weak`: current net, own
  search, `maxVisits` uniform in `q4PopulationWeakVisits` = {1,2,4,8,16,32}, temperature (early = late) uniform in [0.5, 1.5].
  `snapshot`: one of the `q4PopulationNumSnapshots` = 3 most recent models in `models/` older than the current net,
  `maxVisits = 100`, temperatures 0.60 / 0.20 (the match values); weak and snapshot searches have no root noise, root policy
  temperature 1, one root symmetry. `grudge`: target = a uniformly chosen learner seat. All keys are required (hard errors).
- **RNG:** the composition is drawn from its own stream (`Rand(seed + ":population")`), not from the game RNG, so an all-learner
  game does not depend on the population settings (P1).
- **Players:** the learner seats share one `Q4S::Search` (tree reuse across all plies); every other seat has a q4bot or its
  own `Q4S::Search` (weak: the current net, switched with the learners' net by `switchNetsMidGame`; snapshot: the older net). After
  every ply every search gets `makeMove`. Learner turns are unchanged (full / cheap, noise, reduced visits, forks, side
  positions, eliminations).
- **Observer rows:** at a non-learner seat's ply the learners' search first runs the cheap-search settings (min(maxVisits,
  `cheapSearchVisits`), no root noise), giving the root value vector (TD chain, value surprise, C20–24); then the seat's own player
  moves. Written with target weight 1 before surprise weighting, policy surprise 0, C26 = 0, zero channel 0, C29 = 1 with the
  played move, C53 = observer visits, C28 = 0 on a learner row followed by an observer row. Side positions are generated on learner
  turns only and have C61 = 0 (they are searched by the learners' search whoever would move there).
- **Snapshots:** a second `Q4SelfPlayManager` (no latest-model semantics, `loadModelNoDataWritingLoop`), refreshed whenever the
  current net changes (log line `Snapshots for population games (current X): ...`); each game acquires the current snapshot nets
  for its duration. Snapshot evaluators use `q4PopulationSnapshotCacheSizePowerOfTwo` = 18 (the learners' cache is 2^20 × ~4.7 KB).
- **Records / logs:** each record names the seat kinds (`type`, `net`, `visits`; grudge in the name, `Seat 2 >0`). The per-net
  log line (every `logGamesEvery` games, and `Final ...` at the end of a net's cycle) adds the learner seats' points by number of
  learners and by opponent kind. Example from the S3 held-out run (400 games, current net after 4 cycles):

```
learner win rate by number of learners: 1: 10.7% per learner seat (117 games) 2: 10.7% (103) 3: 17.4% (107) 4: 25.0% (73)
by opponent kind (learner / opponent points per seat ...): weak: 17.2% / 23.4% (129) snapshot: 18.8% / 11.5% (150)
  greedy: 1.6% / 69.5% (75) randomPawn: 22.3% / 1.7% (66) basher: 0.0% / 90.4% (77) grudge: 2.3% / 51.7% (79)
```
  (a net trained for ~10 minutes: it loses to greedy / basher / grudge, as the R6 ladder had it.)

**Questions I had to decide on (please check):**
1. *C60 and bit-identity.* The prompt asks for C60 = 2 and for `q4PopulationMixedProb = 0` data bit-identical to the Part 0 head. These
   cannot both hold for column 60: I wrote C60 = 2 always, and P1 / §1 compare everything else bit for bit (the new npz key
   `metadataInputNC` of Part C is of course new too).
2. *Metadata at deeper nodes.* The prompt (and Plan §12.2) freeze one vector, encoded for the root seat. A node whose mover is
   another seat sees the board in its own relative order but the style in the root's. I implemented what is written; Round 8's
   opponent-aware search has to decide this.
3. *Tree reuse and stale evaluations.* After `makeMove` + `setStyleFeatures` the root is re-evaluated with the new features (a
   dirty flag; with `rootNumSymmetriesToSample > 1` as in self-play KataGo's recompute already did), deeper nodes keep the
   evaluation they got with older features.
