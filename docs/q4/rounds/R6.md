## 1. Part A: the one-hot search-policy target

### 1.1 Root cause

`Search::getExploreSelectionValueInverse` (`cpp/q4/search/q4searchexplorehelpers.cpp`) had its first two parameters
swapped to `(exploreScaling, exploreSelectionValue, nnPolicyProb, childUtility)`; its only caller
`getReducedPlaySelectionWeight` passes KataGo's order `(bestChildExploreSelectionValue, exploreScaling, ...)`. The
"retrospectively wanted weight" of every non-best root child was therefore about 0, and `getPlaySelectionValues`
(whose root reduction ends in `ceil(reduced)`) returned a one-hot vector: the policy target, and the chosen move, since
self-play moves are drawn from the same values (the temperature had no effect). Fix: definition and header in KataGo's
order (`cfc9379e` is the loss, `92ede4df` this).

### 1.2 Reviewer's check, reproduced

`test_c7_search_policy_target_is_not_one_hot` (`q4selfplay`, `b1c32_q4` random net, `maxVisits=100`,
`cheapSearchProb=0`, 2 games, 40 plies): 74 full-search rows, **mean C32 = 1.847, mean nonzero C0 slots = 11.09**
(`pytest -s -k c7` prints it). On the binary built before the fix the same test fails with mean C32 = 0.0.

### 1.3 Tests that would have caught it

| Test | What | On the old (swapped) code |
|---|---|---|
| T29 `testq4search.cpp` | after a 200-visit search on the start position: ≥ 3 nonzero `getPlaySelectionValues`; every non-best child equals `ceil(min(childWeight, w))` with `w = exploreScaling * policy / (bestExploreSelectionValue - utility) - 1` recomputed from the formula (no LCB: the 10-argument overload with `neverUseLcb`), and is nonzero when `w > 1` and it has ≥ 2 edge visits; `getPolicySurpriseAndEntropy`: search entropy == entropy of the normalized values, policy entropy == entropy of the NN policy | `Failed test assert: numNonzero >= 3` (1 of 10 nonzero) |
| T30 `testq4search.cpp` | `getExploreSelectionValueInverse(getExploreSelectionValue(w)) == w` for 6 settings, the clamp to 0 and the `1e100` guard | round trip fails |

already right.

## 4. Part C: evaluation and gating

### 4.1 `q4match`

```
katago q4match -config cpp/configs/q4/match/<bench>.cfg -output games.sgfs [-summary s.json] \
    -override-config "player_cand=search:<model.bin.gz>@200,..."
```

Config: `players = a,b,...`; `player_<name> = search:<model>[@visits]` or a `q4bots` name (`random`, `randomPawn`,
`greedy`, `basher`, `grudge`); `tables = t1,t2`; `table_<t> = slot,slot,slot,slot` (a slot is a player name, `grudge`
slots are written `name>k`: target = the player in slot k, whatever seat it sits in), `table_<t>_openings = N`;
`numGameThreads`, `maxPlies`, `openingPliesMin/Max`, `openingWallProb`, `seed`; everything else is the search / NN
configuration of `q4_match_common.cfg` (`@include`d). Config errors (wrong slot count, unknown player or bot, a grudge
without target or a target on another bot) are hard errors.

**Rotations.** Rotation r puts slot (s + r) mod 4 in seat s. A table gets its *distinct* rotations: ABAB two, `cand ref ref
ref` four, a table of one player one. Over them every player sits in every seat equally often. **Openings** are shared
by all rotations of an index and by all tables. The first-move advantage shows in the seat win rates of the report.

### 4.2 Reports and ratings

`python q4/match_report.py games.sgfs [--json out]`: per table and player: wins, win rate (wins / games), win rate per
copy (wins / (games × copies); 25 % = even), score (a draw is 1/4 per seat), 95 % percentile bootstrap CIs over openings
(the rotations of an opening are not independent); seat win rates; draw rate and its reasons (`maxPlies`, `repetition`);
mean length in plies. `python q4/rating.py games.sgfs --anchor random` prints the Bradley–Terry table.

**Pairs.** A game with winner W is one win of W over each *other seat* (3 pairs; two seats of the same player make no
pair). Under Plackett–Luce winner sampling this is exactly Bradley–Terry-consistent (`S_ij / N_ij = π_i / (π_i + π_j)`).
The Duel ladder counts a draw as half a win for each side, so a drawn game gives every pair of different players at the
table half a point each with weight 1/2 per pair (5–6 pairs × 1/2 ≈ the weight 3 of a decided game). The fit is
`quoridor_arena.elo.fit_bt` (maximum likelihood with one virtual draw per pair that met, so 0 % / 100 % pairs stay
finite), Elo scale, `random` = 0; intervals: 1000 resamples of the (table, opening) units, as the Duel ladder resamples
paired units. A draw that is independent of strength compresses the scale (the test below shows it keeps the order).

[-quit-if-no-nets-to-test]`: for each candidate it plays the `abab` table (candidate, current, candidate, current; 2
distinct rotations × `gateOpenings`), and, if `gateBenchStrong` is set, the mixed table (candidate / strong / 2 weak
bots) for the candidate and for the current net on the same `gateBenchOpenings` openings. **Accept iff** the
candidate's ABAB score (win 1, draw ½) ≥ 0.5 (a tie accepts, as Duel's) **and** the paired per-opening difference d of
the benchmark points (candidate − current) does not satisfy `mean(d) + 1.96 · stderr(d) < 0`. The candidate directory is
moved to `A` or `R`; `O/<candidate>/` gets `games.sgfs` and `decision.json`. The decision is `q4gating.h`
(`Q4Gate::decide`), tested on canned results (M5).

`USEGATING=1 python/selfplay/q4_synchronous_loop.sh ...` exports to `modelstobetested/`, runs the gatekeeper (config
archived with `q4_match_common.cfg`; `GATEKEEPER_EXTRA_ARGS`, `GATEKEEPER_TIMEOUT`) before each self-play, and uses
`export_model_for_selfplay.sh ... 1`. Off by default.

## 7. Open questions

1. **The nets lose to `greedy` and `basher` and never wall.** After 13 minutes of self-play with four copies of the same
   net the games are 37 plies of racing, and three `grudge` bots win 100 % against the candidate (§4.3). The population
   self-play of Plan §11 (bots in the pool, in particular `basher` and `grudge`) is what this table is for; its first
   test is whether the candidate in bench (c) ever wins.
2. **Draws in the rating.** Draws that are independent of strength compress the Elo scale (a drawn game is half a point
   for every pair). Self-play games of the early nets have 5–24 % draws; the ladder games here had none, so the effect
   is not visible in §4.6.
3. **CI of the win rates** is a bootstrap over openings; with fewer than ~20 openings it is unreliable.
4. **The first ladder is short** (13 minutes, four cycles), and `s3` / `s4` are not separable. A longer run is a matter
   of GPU time, not code.
5. **`test_muon_state_loading.py` / `test_ddp_training_paths.py` / `test_fused_kernels.py`** fail on `main` too (§5.3).
