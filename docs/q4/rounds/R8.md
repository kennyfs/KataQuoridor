## 1. Part 0: fixes from the R7 review

### 1.1 Metadata perspective at non-root nodes (Plan §12.2)

`Search` keeps `styleBySeat[4][76]` = `style.encode(j)` of the real position for every seat `j`, set by
`setPosition(Q4History)` and by the new `setStyle(const Q4StyleTracker&)` (replaces `setStyleFeatures`). `initNodeNNOutput`
feeds `styleBySeat[thread.state.board.toMove]` and hashes that vector into `nnHash` / the NN cache key. The root
re-evaluation after tree reuse stays: `rootStyleDirty` is set when the *root mover's* encoding changes. Callers updated:
`q4play` (after every ply; side positions now also carry the tracker, `Q4SidePosition::styleTracker`), `q4matchengine`;
`q4qtp` always calls `setPosition(history)`. Deeper reused nodes keep their older evaluations (as in R7).

### 1.2 Observer row weight

`q4PopulationObserverRowWeight` (required key; 0.25 in `q4_selfplay.cfg`) is the target weight of an observer row before
KataGo's surprise weighting and stochastic integerization. Measured (P5, seeded, `q4PopulationMixedProb = 1`, 60 games,
`maxVisits = 24`; `pytest tests/test_q4_selfplay.py -k p5 -s`):

| observer weight | learner rows | observer rows | observer rows per observer ply | observer share of main rows |
|---|---:|---:|---:|---:|
| 1.0 | 694 | 620 | 0.409 | 47 % |
| **0.25** (default) | 437 | 146 | 0.095 | **25 %** |
| 0.0 | 309 | 0 | 0 | 0 % |

At the default *mixed probability* 0.5 (Part C point p4, `tf2_b4c192_q4-meta`, 225 s): 12,688 learner and 4,256
observer rows/h, observer share **25 %**. Note: observer rows per ply (0.095) are below learner rows per ply (0.27)
because the observer rows have policy surprise 0 and lose weight in the policy-surprise redistribution; I left this as
KataGo's weighting does it (the prompt's "like any other turn").

## 2. Part A: opponent-aware search (Plan §12.3)

- `Q4S::OpponentMode` and `Search::setOpponentModel(mode, ownSeatMask)` (changing either clears the tree); not in
  `SearchParams`. `isOwnSeat(s)` = `s` is the root mover or in the mask. Self-play: the learners' search gets the mask of
  the learner seats (all-learner games: all four, so the mode has no effect); weak / snapshot seats' searches get their own
  seat. q4match: each search player's own seat; q4qtp: the seat to move.
- Own nodes: unchanged (PUCT, channel 0, noise at the root). Opponent nodes: `style` = the same PUCT code with
  `stylePolicyProbs` as the prior (FPU's visited policy mass from it too); `expect` =
  `selectChildByStylePolicyShare`: argmax `P_i − N_i / (N + 1)`, `N_i` = edge visits + virtual losses, unvisited children
  `N_i = 0`; no utility term, no FPU. Value backup unchanged.
- `NNOutput::stylePolicyProbs` is allocated only when the mode is not `maxn`. `nnPolicyTemperature` now applies to the
  channel-1 softmax too (`Q4NN::evaluate`; nothing read channel 1 with a temperature ≠ 1 before). Root noise copies it
  untouched.
- **Decision:** the root seat is always own, also in the observer search of a non-learner ply (the plan: "the root seat,
  and in self-play every learner seat"); the observer search then searches that seat's move with its own PUCT.
- Config key `q4OpponentMode` (required) in `q4_selfplay.cfg`, `q4_match_common.cfg` (all match / gatekeeper / bench
  configs include it), `q4qtp.cfg`, `q4search_test.cfg`; all `maxn`. q4match reads it only when a table has a search player.

## 3. Part B: the formal-run launcher (Plan §15)

`python/selfplay/q4_formal_run.sh BASEDIR [NAMEPREFIX] [TRAININGNAME]` sets and runs `q4_synchronous_loop.sh`:
`tf2_b4c192_q4-meta`, `TRAIN_EXTRA_ARGS = -use-aurora -wd-floor-frac 0.5 -lr-schedule (0,8.0),(4M,4.0),(12M,2.0)
-max-val-samples 10000`, batch 256, `MAX_TRAIN_PER_DATA = 6`, `VALIDATE = 1` with `VALIDATION_PROP = 0.05`, `USEGATING = 0`,
`NUM_GAMES_PER_CYCLE = 2500`, `KATAGO_BIN = cpp/build-cuda/katago`; all overridable from the environment.

- **Shared-file changes:** `shuffle.sh` gets `VALIDATION_PROP` (default 0.01 → `-only-include-md5-path-prop-lbound 0.9900`, the
  value it had: Duel unchanged); `q4_synchronous_loop.sh` gets `POST_EXPORT_HOOK` (run after every export with the cycle
  number; a failure is logged to `logs/posthook.txt` and does not stop the loop).
- **Hook** `q4_formal_eval.sh`: every cycle one line of `summary.tsv` (`python/q4/formal_summary.py`: last train / val
  p0, value and style losses from `metrics_*.json`, the self-play net's games, draw rate with maxPlies / repetition parts,
  rows written, rows per hour of cycle, learner / opponent points by opponent kind); every `EVAL_EVERY` exports a q4match of
  the newest export vs the previous evaluated one (the init net the first time) and the bots — `formal_eval.cfg`: tables
  new-vs-prev (ABAB, 26 openings = 52 games), new vs greedy/basher/randomPawn, prev vs the same, new vs 3 × `grudge>0`
  (bench (c)), bots only; 13 openings × 4 rotations each, ≈ 260 games at 100 visits — appended to `eval/ladder.jsonl`, then
  `rating.py` on the whole file and `match_report.py` of the evaluation into `eval/ratings.md`.
- **LR schedule across cycles (read in `train.py`):** `get_effective_lr_scale` picks the schedule value by
  `train_state["global_step_samples"]`, which is saved in `checkpoint.ckpt` and reloaded each cycle (`load()` returns
  `train_state`; only a fresh model starts it at 0), so the thresholds count *training samples over the whole run*.
  The warmup is a separate factor on top: `warmup_scale` = 1/20 below 250k samples, rising stepwise to 1 at 2M
  (`-no-lr-warmup` not passed: the run starts from scratch, unlike Duel's run3a continuation). So the effective scale is
  8 × warmup until 2M samples, 8 until 4M, 4 until 12M, 2 after; the weight decay uses (scale × warmup)^0.75 as well. With
  `MAX_TRAIN_PER_DATA = 6`, 4M / 12M samples correspond to ≥ ~0.67M / 2M self-play rows.
- **Smoke test** (Eigen, `b1c32_q4-meta`, 2 cycles × 60 games, `maxVisits=16`, `EVAL_EVERY=1`, `EVAL_OPENINGS=1`,
  `EVAL_VISITS=8`; command in §7): exit 0; two evaluations (40 games in `ladder.jsonl`, `ratings.md` with 8 players);
