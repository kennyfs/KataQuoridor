## 3. Training-Row Format as Implemented

The full training-row format is documented in `docs/q4/Q4IO.md` §8.

### 3.1 Overview of NPZ Keys
Each `.npz` archive contains 7 arrays:
1. `binaryInputNCHWPacked` (uint8 `[N, 27, 16]`): 27 spatial input channels bit-packed per channel (121 bits zero-padded to 128, big-endian), with channels 10–14 written as 0.
2. `spatialDistNCHW` (uint8 `[N, 5, 11, 11]`): Raw distances of channels 10–14 (255 = unreachable).
3. `globalInputNC` (float32 `[N, 28]`): 28 global features.
4. `policyTargetsNCMove` (int16 `[N, 3, 363]`):
   - C0: Search policy target (pruned visit counts).
   - C1: Action actually played (one-hot with value 1).
   - C2: Next seat's search policy target (uniform with weight 0 if unavailable).
5. `globalTargetsNC` (float32 `[N, 64]`): Global targets (detailed below).
6. `scoreDistrN` (int8 `[N, 1]`): All zeros (key compatibility).
7. `valueTargetsNCHW` (int8 `[N, 12, 11, 11]`):
   - C0–3: Cells visited by pawns of relative seats 0..3 from this row to the end of the game.
   - C4–11: Walls placed from this row on by relative seat k (channel `4 + 2k` vertical, `5 + 2k` horizontal). All 0 on side positions.

### 3.2 `globalTargetsNC` Columns
All value vectors are in relative-seat order `[me, next, across, previous, draw]`:
- **C0–4:** Final game result (one-hot relative winner or draw).
- **C5–9:** TD value target (`nowFactor = 1 / (1 + 121 · 0.176)`).
- **C10–14:** TD value target (`nowFactor = 1 / (1 + 121 · 0.056)`).
- **C15–19:** TD value target (`nowFactor = 1 / (1 + 121 · 0.016)`).
- **C20–24:** Search value target of this turn (`nowFactor = 1.0`).
- **C25:** Row weight.
- **C26:** Policy target weight.
- **C27:** Outcome weight (0 on side positions).
- **C28:** Next-seat policy target weight.
- **C29:** Style-policy target weight (1.0 on all written rows).
- **C30–32:** Policy surprise, policy entropy, search entropy.
- **C33:** `1 - weight(TD value targets)`.
- **C34:** `1 - weight(value targets)`.
- **C35:** Plies from this row to the end of the game.
- **C36–39:** Walls-only distance to center of relative seat 0..3 at game end.
- **C40–43:** Weight of C36–39 (0 if seat was eliminated before end).
- **C44–49:** 128-bit game hash in six chunks.
- **C50:** Ply of this row; **C51:** First training ply; **C52:** Game mode (0 normal, 2 fork).
- **C53:** Unreduced search visits.
- **C54:** Raw NN utility of seat to move.
- **C55:** Number of alive seats at this row.
- **C56:** `repetitionDrawCount` of the game (0 = off); **C57:** `maxPlies`.
- **C58:** 1 if game hit `maxMovesPerGame` without a result.
- **C59:** 1 if game finished and is not a side position.
- **C60:** Q4 data format version (1).
- **C61–63:** 0.

## 6. Open Questions & Pluggable Features

1. **Reanalysis (`useReanalyze`):**
   - In Duel / KataGo Go, `useReanalyze` takes cheap-search positions and performs full MCTS searches after the game ends.
   - For Q4, the plumbing was removed from `Q4PlaySettings` to avoid unnecessary complexity during initial self-play. If re-enabled later, it would plug into `Q4GameRunner::runGame` right after game completion by iterating over `gameData->sidePositions` (or cheap search markers) and dispatching full `runWholeSearch` before passing the game to `manager->enqueueDataToWrite`.
2. **In-Tree Positions (`recordTreePositions`):**
   - If enabled in future iterations, in-tree node recording would plug into `extractPolicyTarget` and `SearchNodeTable` traversal at the end of each search, storing subtree states as additional `Q4SidePosition` instances with outcome weight 0.
3. **Round 5 Training Pipeline:**
   - Round 5 will load the exported 7-tensor NPZ files using Python PyTorch / DDP data loaders, applying 8-fold dihedral symmetries to spatial inputs and targets. All keys and shapes produced by Round 4 match `docs/q4/Q4IO.md` §8.
