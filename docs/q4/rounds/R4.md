### 2.7 R4b/c changes in `cpp/q4/q4board.{h,cpp}` (commit `35477cce`)

- `struct Q4Bits121`: 121-bit set in two `uint64_t` (`lo` = cells 0..63, `hi` = 64..120, bits above 120 kept
  zero) with `|`, `&`, `==`, `test`, `set`, `clear`, `assign`, `shl<n>()`, `shr<n>()`.
- Members `canN`, `canE`, `canS`, `canW`: bit c set iff the step from c is open. `syncCanMasks(c)` refreshes
  one cell from `blocked[c]`; it is called in `initGridBoundaries` (all cells) and for the four touched cells in
  `addWallToBlocked` / `removeWallFromBlocked`. These are the only writers of `blocked[]` (checked with
  `grep -rn "blocked\[" cpp/q4`); `Q4Board` is copied by the implicit copy constructor/assignment, which copies
  the masks with `blocked[]`.
- `isLegalWallBruteForce`: `wallConflicts` check first (as before), then `needed` = alive pawns not on the
  center, copy the masks, clear the four edges the wall closes, flood from `CENTER_CELL` with
  `R | (R&canN)<<11 | (R&canE)<<1 | (R&canS)>>11 | (R&canW)>>1`, return as soon as `needed ⊆ R`, illegal when
  `R` stops growing. Row wrap is prevented by the board-edge bits in `blocked[]`; a debug-only `assert`
  checks that the masks have no x = 10 cells in `canE` and no x = 0 cells in `canW`.
- `isGeometricallyLegalWall` (path-edge prefilter unchanged) calls `isLegalWallBruteForce`.
- `isLegalWallBruteForceBFS`: the previous body, used only by tests and `q4tool wallbench`.

### 5.2 Memory: NN cache fill (C6/C7 re-run for 3 minutes)

The NN cache holds `shared_ptr<NNOutput>`; for Q4 each `NNOutput` (1256 B) points to a `Q4RawNNOutput`
(3432 B), both from `make_shared`, so a filled entry is ≈ 4.7 KB and 2^20 entries ≈ 4.9 GB. RSS grows until the
cache is full, then flattens:

C7 (CUDA): `/tmp/claude-1000/rss_run.sh <out> 180 ./cpp/build-cuda-rel/katago q4selfplay -models-dir /tmp/q4models/b2c64_q4 -config cpp/configs/q4/training/q4_selfplay.cfg` (VmRSS every 30 s, then SIGINT)

| t (s) | 30 | 60 | 90 | 120 | 150 | 180 |
|---|---|---|---|---|---|---|
| RSS (MB) | 5565 | 6755 | 7857 | 8208 | 8271 | 8290 |

Log: `GPU -1 finishing, processed 8036206 rows 45401 batches`, `Total valid games: 364`, runtime 182.35 s.

C6 (Eigen, the R4 command shape: `-models-dir cpp/tests/models`, no cache override):
`... 180 ./cpp/build-eigen-release/katago q4selfplay -models-dir cpp/tests/models -config cpp/configs/q4/training/q4_selfplay.cfg -override-config "numGameThreads=8"`

| t (s) | 30 | 60 | 90 | 120 | 150 | 180 |
|---|---|---|---|---|---|---|
| RSS (MB) | 2727 | 3916 | 4451 | 4692 | 4801 | 4854 |

Log: 8 server threads processed 5,001,708 rows in total, `Total valid games: 306`, runtime 181.37 s.

Both runs evaluate several million rows, far more than the 1,048,576 cache slots, and RSS flattens once the
cache is full. This is the cause of the RSS growth reported in R4's C7 run (then with 2^21 slots, ≈ 9.8 GB of
cache); it is cache fill, not a leak.
